vvv-claude-kit

Персональный набор скиллов и хуков для Claude Code вокруг процессного плагина superpowers. Архитектура трёхслойная: правила сессии гарантированы хуком в каждом контексте, механическая защита ставится в конкретный проект скиллами-установщиками (движок копируется в проект, регистрируется в его settings.json), глубокие протоколы разработки доверены реактивному срабатыванию по точным описаниям. Оценки ниже — собственная решимость агента: насколько каждый компонент нужен в работе.

6/10
Почему 6: ядро (политика + экономика) гарантировано инъекцией по фиксированной цене; механическая защита точечно-проектная — ставится один раз, работает всегда, в неинициализированных проектах её нет (осознанная модель); дисциплина разработки реактивна, и её дно — потеря протоколов после компакции длинного контекста. Чего набор не заслужил — удаления: не убирать ничего; живых улучшений не осталось.

Что это за компонент

Персональный плагин для Claude Code из собственного marketplace: /plugin marketplace add vadimvinokurov/vvv-claude-kit. Разделение труда с superpowers: тот держит процессные пайплайны (brainstorming → план → TDD → ревью), этот кит — операционный слой: политика поведения, экономика запросов, acceptance-контракты, защита. Скиллы четырёх функций: правила сессии (инъектируются хуком всегда), протоколы (реактивно по описанию задачи, с выход-чеками и wiring-сетью между собой), установщики (создают проект-локальные хуки с опросом и верификацией), агент-сайд правила (доставляются в контекст заспавненного агента инструкцией спавна). Хук у плагина один — механика защиты живёт в проектах.

Как работает

начало каждой сессии · гарантия
Хук load-session-rules вкалывает common-rules (политика) и token-economy (экономика + фильтр и форма спавна) в контекст каждой сессии. Единственный гарантированный канал набора; работает в любом проекте, включая неинициализированный, где ничего больше и не включено.
я сам · по совпадению с задачей
Протокольные скиллы срабатывают реактивно. Вход — флагман testable-apps-development: три строки exit-чека решают зону; правила 3/4/6 и GUI-компаньон зовут companions по имени (dual-path-oracle, golden-rebaseline, headless-text-rpc, ui-development). У реактивного слоя есть свои дешёвые входы: ui-development открывается решателем состояния диска. Осознанная цена слоя: текст протоколов не переживает компакцию длинного контекста.
раз на проект · по опросу
Скиллы-установщики — protect-secrets и release-tag-gate — спрашивают только то, что код проекта не отвечает (какие паттерны защищать; какие гейты составляют релиз), копируют движок в .claude/hooks/, слиянием регистрируют PreToolUse в проектном .claude/settings.json и верифицируют установку реальными вызовами до «готово». Защита затем механическая и не зависит от дисциплины агента.
релиз · собственный репозиторий
Dogfooding: кит накормил себя сам — этот репозиторий защищён собственными установленными хуками; release_gates.sh гоняет 4 гейта и пишет маркер, проект-локальный tag-gate не пускает тег без зелёного маркера на текущем HEAD. Тот же список гоняет CI. (Фирменный факт сборки: свежеустановленный хук заблокировал собственную верификацию агента — механика проверена живьём.)

Скиллы

7–10 держу в работе постоянно 4–6 регулярный или точечный инструмент 0–3 редкий жанр
инъектируются в каждую сессию
common-rules8/10

Политика каждой сессии: не выдумывать, думать до кода, простота, хирургические правки, когда спрашивать. Гарантирована инъекцией с первого хода.

Почему так: формирует базовое поведение — без неё агент регрессирует к дефолту «сделал побольше». Платёж фиксированный и предсказуемый, открытие частое.

Оставить как естьСжат. Goal-driven execution свернут к одной ссылке: процессы (TDD, verification, планы) — скиллы superpowers, common-rules остаётся политикой, не процессом; «No hidden memory» и остальные разделы уникальны и не тронуты.
token-economy8/10

Экономика каждой сессии: ход = платный запрос, чтение узко, правки только Edit/Write, расписание гейтов, «три удара — стоп», фильтр делегирования (спавн оправдан при >3–5 вызовов/гейт-цикла + named file boundary; контекст только из диалога → выпиши в tracker или инлайн), форма спавн-промпта с контрактом отчёта («all green» — не отчёт) и drift-правило координатора (~2× бюджета без чекпоинта → стоп и salvage). Гарантирована инъекцией.

Почему так: напрямую уменьшает бесполезные запросы, за которые платит пользователь; решение о спавне, его форма и правило остановки всегда в контексте без отдельного скилла — агентская половина делегирования живёт в своём скилле.

Оставить как естьSupervision-дыра закрыта с обеих сторон: агентские обязанности — в `/subagent-rules` (доставка строкой спавна), координаторский drift-контроль — вернулся одной строкой в §5.
реактивные протоколы разработки
testable-apps-development6/10

Флагман и роутер: семь правил headless-разработки нового кода (чистое верифицируемое ядро + тонкий автогенерированный UI, acceptance командой без экрана). Трёхстрочный exit-чек отсекает рефакторинг/фиксы до чтения правил; правила 3/4/6 и GUI-компаньон называют companions по имени.

Почему так: в приложении-центричной практике новый код возникает постоянно, и в момент срабатывания резко сокращает итерации — acceptance задан до кода.

Оставить как естьСодержательно готов: exit-чек, полная wiring-сеть к друзьям, детализация Scope без дублей. Доработок не осталось.
headless-text-rpc5/10

Механика приёмки интерактивных способностей: способность и её проверка существуют как команда до разметки; кнопка и команда — один хэндлер; типизация на одной границе; фейки повторяют реальную форму команд; снапшот состояния — ground acceptance.

Почему так: ленив и грузится в момент добавления способности или вайринга проверки; правило 6 флагмана зовёт по имени. В приложениях срабатывает регулярно.

Оставить как естьЕдинственный владелец механики; слияние сделало бы её обязательным налогом каждой headless-сессии — включая CLI и утилиты без state.
dual-path-oracle5/10

Каждая неочевидная оптимизация: наивный референс-близнец в том же changeset, вечный именованный тест на равенство на идентичных входах, измеренное и записанное ускорение.

Почему так: без близнеца ускорения «на глаз» небезопасны. Триггер усилен пользовательскими фразами («оптимизируй / ускорь / латенс / performance») — самым раненым триггером набора.

Оставить как естьПротокол полный, триггер ловкий, правило 3 флагмана зовёт по имени. Доработок нет.
golden-rebaseline4/10

Сквозной протокол триажа провалившейся golden-компарации (UI-рендеры и data-корпус): сначала diff, классификация intended/regression, перезапись только с записью before/after; нулевой diff при видимой разнице = изменилась логика, не разметка.

Почему так: без протокола золотые перезаписываются «чтобы зелёное» — именно тот провал, который он описывает. Живёт над двумя доменами, оба родителя зовут его по имени.

Оставить53 строки, ленив, точный событийный триггер. Единственный скилл набора, чья ценность целиком в аварийном моменте — и в нём незаменимый.
ui-development4/10

Visual-пайплайн: живые исходники компонентов — единственная правда дизайна, doc и золотые PNG генерируются из них, acceptance оффлайн по component × variant goldens плюс композиты, реальное окно только на вехах, image-budget против повторных чтений картинок.

Почему так: в GUI-проектах главный актив (117 строк, самое дорогое чтение), вне их не участвует; решатель в первых строках определяет состояние инфраструктуры бесплатно.

Оставить как естьГотов. Entry-чек (компоненты есть → workflow; только hand-made doc → migrate; ничего → bootstrap) отправляет в нужную ветку без дублирования содержимого.
release-gates4/10

Протокол релиза: тег только после зелёного прогона release_gates.sh на том же коммите (маркер как доказательство); список гейтов — скрипт, не память; CI-провал после зелёных локальных гейтов — задача по diff сред, не повторный пуш.

Почему так: редкое событие, гасит самый дорогой класс ошибок — «выпустил и забыл прогнать».

ОставитьПротокол и механика разделены чисто: знания (как публиковать при провале) здесь, исполнение (что отклонять) — у установщика.
установщики проект-локальных хуков
protect-secrets7/10

Установщик: спрашивает паттерны (дефолт: `.env`, `.env.*`, `*.pem`, `*.key`, `.secrets`/`.secret`; исключения `.example`/`.template`), копирует движок в проектный `.claude/hooks/`, слиянием регистрирует PreToolUse в `.claude/settings.json`, верифицирует установку реальными deny/allow пробами.

Почему так: срабатывает раз за проект, но ставит страхование самой дорогой ошибки агента — секрет в репозитории; оценка вшивает и ценность поставленной защиты: она потом работает всегда и без дисциплины агента.

ОставитьКонстанта модели, осознанная: неинициализированный проект не защищён — платит владелец при инициализации. Движок — редактируемый код проекта, паттерны расширяются в копии.
release-tag-gate6/10

Установщик: находит гейты в репо (тест-раннер, package scripts, Make, типчек), опросом утверждает состав и порядок (дефолт протокола: полный suite → strict types → интерфейсные → goldens), пишет проектный release_gates.sh (с проверкой, что команды существуют), ставит движок + регистрацию, гоняет гейты и верифицирует сам тег-гейт.

Почему так: раз за проект ставит отказ «тег без зелёного маркера на текущем HEAD» — страховку «не верить памяти» в дороге релиза. GATES — знание проекта; скилл ставит механику, протокол держит семантику.

ОставитьКлючевая деталь встроена: гейт, который не запускается, — ложный маркер, поэтому установщик проверяет существование каждой команды до записи.
агент-сайд правила делегирования
subagent-rules5/10

Обязанности заспавненного агента: бюджет — alarm, не квота (чекпоинт-заметка, затем стоп или одно продление с потолком); чекпоинт на каждой вехе; detach фоновых ожиданий вместо sleep-polling; отчёт с gate outputs, не с претензиями.

Почему так: восстанавливает агентскую половину удалённого контракта прямо там, где она применяется — в одноразовом контексте делегата, который никто не перечитывает; главный контекст платит строкой-указателем в шаблоне спавна.

Оставить как естьДоставка закреплена механически: «First action: load /vvv-claude-kit:subagent-rules» — обязательный элемент спавн-промпта в token-economy §5, не надежда на вспоминание.

Хук плагина

load-session-rules8/10

Единственный плагинный хук (SessionStart): вкалывает два файла правил сессии — common-rules, затем token-economy — в контекст каждой сессии любого проекта.

Почему так: минимальный по объёму и максимальный по надёжности канал набора — политика со первого хода, без мандатных посредников. Форма после всех метаморфозов дня: раньше там был мандат using-skills (двойная инъекция с superpowers), теперь — ровно два рабочих файла и ничего больше.

Оставить как естьОбратимость сохранена: убрать один cat — token-economy возвращается в реактивный режим без правки контента. Сейчас гарантия выбрана владельцем явно.

Сводка рекомендаций

Убрать: ничего. 12 компонентов после всех перестроек — каждый несёт протокол или страховку, которых нет нигде больше. Архитектурные решения (инъекция правил, защита по проекту, реактивная дисциплина, агент-сайд доставка) приняты владельцем; живых улучшений не осталось.

Полезность зависит от типа проекта

6-7
Dev-проект после инициализации (обе защиты поставлены)
Полная сборка: политика и экономика гарантированы, секреты и релизы — механически, протоколы разработки — реактивно. Естественный контекст плагина.
5
Dev-проект без инициализации
Только правила сессии + протоколы по доверию. Работает, но механическая защита нулевая — состояние «не поставил», а не «не нужно».
3-4
Исследовательский репозиторий (конспекты, статьи, анализ)
Правила сессии + reactively testable-apps на выживающий код экспериментов; exit-чек сдерживает церемонию. Протоколы UI и релизов не задействованы.
5
Небольшие правки, короткие задачи
Ядро правил сессии окупается мгновенно; тяжёлые протоколы не успевают ничего стоить — реактивность их просто не поднимает.
